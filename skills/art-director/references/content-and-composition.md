# Content and composition

Read this when structure, grouping, or section rhythm is in play. Skip it
when the request is type, color, or a single control.

## Roles, not equal blocks

Give each band a job:

- **Lead:** the one thing a visitor should understand first.
- **Proof:** the artifact, data, case, or sample that makes the lead true.
- **Support:** secondary services, notes, or context.
- **Action:** the next step, with a label that names the task.

A brief with five bullets is not five sections of equal height. Merge
weak items. Cut sections that only repeat the lead in vaguer words.

Do not confuse page type with organization type. "Landing page" does not
mean hero, logo row, three cards, quote, and footer.

## Density

Match density to the task:

- Reading and persuasion need air around the lead and a stable measure.
- Comparison needs aligned attributes, not scattered paragraphs.
- Operations need compact, scannable records and persistent context.

Dense is not "ugly" and spacious is not "premium". Wrong density is a task
failure: a dashboard that feels like a brochure, or an essay that feels
like a settings grid.

## Grouping several offerings

Group by visitor job, not by the org chart.

- Unlike offerings: feature one, then name the others as different paths.
- Comparable offerings: a table or definition list beats identical cards.
- A series (issues, case studies, releases): show order, date, or status.

Avoid a grid that repeats the same heading structure with the name swapped.

## Rhythm

Vary section width, density, and media for a reason. A full-bleed proof
after a narrow lead can help. Alternating "text / image / text / image"
is not a strategy.

Asymmetry is a tool, not a requirement. Centered, symmetric layouts are
valid when the content is a single statement plus an action.

Keep source order meaningful. Layout that relies on visual reordering often
breaks on small screens and in non-CSS agents.

## Decision examples

### Multi-product studio

Northglass lists photography retainers, exhibition design, and weekend
workshops. A three-card row treats them as SKUs. Better: open with the
current exhibition (proof), then a retainer inquiry path, then workshops as
a dated list. The visitor can tell which offering is live work and which is
a class.

### Personal developer portfolio

Ada has six shipped tools and one long technical memoir. Equal project
tiles bury the memoir, which is the distinctive piece. Better: lead with
the memoir's opening argument and one screenshot, then a compact index of
tools grouped by problem (data, games, internals), not by recency alone.
