# Visual research

Read this on a **broad DESIGN** or an explicit redesign, when the host can
fetch pages and you can actually see them. Skip it for a one-control REFINE,
and skip the live web if tools are missing.

This pass solves *this brief's* visual problem. It is not a trend harvest
and not a quota. Two to four references are usually enough. Zero is correct
when the user already handed you the references, or when you cannot see.

## Order

1. References the user supplied. Look at those first.
2. The product's own marketing or app, the studio that designed it, or a
   first-party design system.
3. One adjacent artifact that shares the *task* (a reading surface, a
   dispatch board, a workshop landing)—not three near-identical SaaS homes.

Gallery roundups can suggest URLs. Confirm appearance and context on the
origin page. Do not treat a thumbnail grid as the design.

Do not offer three sites from the same SaaS look and call that diversity.

## Seeing vs reading

Fetching HTML or a markdown conversion is not visual inspection. If you
cannot see the rendered screen (browser, screenshot you then look at, or an
image the user attached), do not record the source as visually studied.

If you only have text, you may still note information architecture from
copy. Label that as **source reading**, not visual research.

## Dates

Record **observation date** (when you looked). Do not confuse it with when
the site launched. If you do not know the design's ship date, do not call
it "this year's trend."

## Note template (short)

For each chosen source:

- URL
- Observation date
- Screen or state you actually saw (home, article, app chrome, mobile, …)
- Visitor task on that screen
- One strong visual decision (layout, type, crop, surface—not "it feels premium")
- Principle you can reuse here without copying brand
- Brand-specific trait to leave behind (palette, logo, mascot, distinctive UI chrome)

Do not copy layout, assets, or brand. Especially do not reuse the same
reference the same way on unrelated projects.

## What "principle" means

Reusable: "the product UI is the proof, so the opening viewport is a
cropped working surface, not a slogan over three cards."

Not reusable: Linear's near-black canvas, rounded app frame, and "Sign up"
pill. Those are Linear.

## Offline fallback

If there is no web or browser, stop this pass. Use the studies linked from
`SKILL.md`. Say that live visual research did not happen. The skill must
still work.

## Worked notes (original observation, 2026-09-17)

These notes are from rendered screenshots taken in this skill's authoring
session. They are examples of the template, not a mandatory mood board.
Do not restyle a ceramics studio, a memoir, or an ops board to match them.

### Linear marketing home — product as proof

- URL: https://linear.app/
- Observed: 2026-09-17, desktop ~1440×900 and narrow ~390×844
- Screen: marketing home, first viewport
- Task: understand what Linear is, then sign up or open the product
- Strong decision: the headline is large, tight grotesque type on a near-black
  field, but the *proof* is a real issue view (sidebar + issue title +
  activity) sitting under it like the actual object of sale. Nav is a thin
  hairline bar; primary action is a small filled pill, not a hero button
  the size of the title.
- Reuse: when the distinctive artifact is a working UI, put a cropped,
  believable fragment of that UI in the opening viewport; on a phone,
  stack the claim, then show a tighter crop of the same object (here the
  issue still reads; the sidebar becomes secondary).
- Do not copy: the black/SaaS chrome, the specific issue-tracker IA, or
  the idea that every site needs a floating product window.

### Linear, same URL, narrow viewport

- Observed: 2026-09-17, ~390×844
- Strong decision: they did not scale the desktop nav. Destinations collapse
  away; logo + log in + sign up remain. The product frame is cropped, not
  letterboxed as a tiny desktop.
- Reuse: mobile is a different crop and order, not a percentage shrink.
- Do not copy: hiding information architecture behind a luxury blank.

Further live screens (Vercel, Stripe, studio and reading sites) belong in
the same template **only after you have seen them**. If a later pass cannot
open those pages, do not backfill visual claims from memory of their copy.
